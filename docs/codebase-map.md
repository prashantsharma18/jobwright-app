# jobwright-app: codebase map
Owner: Prashant Sharma · Last verified: 2026-11-11, against commit d612731 (slice 0 merged)
Read this before planning a change. Paths are from the repository root. Each line is FACT (read in the code) unless it
says INFERENCE or "planned" (from the design: `../stories/NEW-jobwright/new-system.md` PATHS, ADR drafts 1 to 13).

## What this service does
Jobwright's application, as a skeleton: the web app (Next.js, the back end for the front end), the API and the worker
(.NET), and their images. After slice 0 the web app serves one page (`/`, the heading "Jobwright"), the API answers only
`/health/live`, and the worker runs the template loop. Planned (part 3): the browser talks only to the web app; the web
app calls the API for the user through the client generated from `api/contract/openapi.yaml` (ADR 0004); the API and the
worker use PostgreSQL 17 with row-level security (ADR 0003) and Keycloak for sign-in (ADR 0002). Nothing calls out
today.

## Key flows
pull request -> .github/workflows/ci.yml -> scripts/check.sh <mode>   each gate is its own job, no `needs:`; each runs
    the same mode a developer runs; browser and budget run in the pinned Playwright image
GET /health/live -> api/src/Jobwright.Api/Program.cs   200 "Healthy" while the process runs; no dependency checks (K2)
GET / -> web/src/app/layout.tsx -> web/src/app/page.tsx   (INFERENCE: statically rendered); the theme switches on a `.dark` class
    that nothing sets yet (dark mode arrives with part 3's theme)
scripts/dev.sh -> PostgreSQL 15432, Keycloak 18080 (containers jobwright-dev-*), API 15080, web 15300, all 127.0.0.1;
    refuses while a k3d cluster runs or a port is taken; random credentials per run, removed on exit

## Where common changes go
- A new page: `web/src/app/<route>/page.tsx`, and add its path to `web/tests/e2e/accessibility.spec.ts` (the list is kept
  by hand, review-record M2). Pattern: `web/src/app/page.tsx`
- A UI component: add it with the shadcn CLI into `web/src/components/ui/`, then compose it in the page. Pattern:
  `web/src/components/ui/button.tsx`
- An API endpoint: contract first in `api/contract/openapi.yaml` with its failing tests (planned, ADR 0004). Pattern for
  an endpoint test: `api/tests/Jobwright.Api.Tests/HealthLiveTests.cs` (WebApplicationFactory)
- A module or a module type: `api/src/Modules/<Module>/` and `<Module>.Contracts/`; add both to
  `api/Jobwright.slnx`, to `IncrementOneModules` and as references of the architecture tests. Pattern:
  `api/tests/Jobwright.ArchitectureTests/ModuleBoundaryTests.cs`
- A NuGet package: its version in `api/Directory.Packages.props` (central pins), the reference without a version in the
  project; restore updates `packages.lock.json`. An npm package: exact version in `web/package.json`. Both ask the owner
  first (new-system.md DEPENDENCIES)
- A CI step: `.github/workflows/ci.yml`, calling a `scripts/check.sh` mode; every `uses:` a 40-character SHA with
  `# vX.Y.Z`

## Traps
- Every command needs the pinned toolchain on PATH: `~/.local/opt/node-v26.13.0/bin` and `~/.local/opt/dotnet-10.0.403`
  (with `DOTNET_ROOT`); the default shell has neither pnpm nor this dotnet.
- pnpm's launcher has no shebang line (its install script was left unrun, E6), so `docker run <image> pnpm ...` fails
  with "exec format error"; run it through `bash -c` or `scripts/check.sh`.
- The host has no Playwright browser; browser tests run in `mcr.microsoft.com/playwright:v1.65.0-noble` by digest
  (the command is in AGENTS.md). A single test file does not build first: run `scripts/check.sh browser` once before.
- `pnpm typecheck` runs `next typegen` first; a typecheck on a tree with stale `.next/types` passed locally and failed on
  a clean checkout (E12).
- `next dev` writes `web/AGENTS.md` when an agent runs it; `agentRules: false` in `web/next.config.ts` stops it (E13).
- The module rule passes without checking anything while the modules have no types (D6, approved exception, expiry
  2027-01-31 or part 3's first module type).
- The dark AC12 projects scan the light page: `colorScheme: "dark"` does not set `.dark` (review-record M1).
- Windows reserves ports from 49152 (WinNAT, E1): the dev ports sit below it; 3000, 3001, 4318, 4444, 9090 and 9091
  belong to the owner's lab.
- Lock files (`web/pnpm-lock.yaml`, `api/**/packages.lock.json`) are restored with `--frozen-lockfile` and
  `--locked-mode` in CI; never edit them by hand.
- The owner's `ai-lab-*` containers share this Docker; touch only `jobwright-*` containers and images.

## Tests
- Web unit: Vitest, `*.test.ts` next to the code (`web/src/lib/utils.test.ts`); no real dependencies.
- .NET: xUnit v3 on Microsoft Testing Platform (xunit.v3.mtp-v2), one project per area under `api/tests/`;
  `dotnet test api/Jobwright.slnx`; in-process host, no real dependencies yet.
- Browser: Playwright in `web/tests/e2e/`, four projects (360 and 1440 px, light and dark) plus `budget`; they start the
  standalone server on 127.0.0.1:15300 from a fresh build; Chromium in the pinned image only.
- Scripts: `scripts/tests/test_dev.sh`, with fake `docker` and `k3d` first on PATH; never touches the real ones.
